# Android-клиент

- UI и клиентская логика — Flutter/Dart; системный VPN и жизненный цикл ядра — Kotlin.
- В рабочей папке автора окружение загружается из `../tools/Enter-MobileEnv.ps1`, SDK и кеши находятся в `../toolchains`. При отдельном клонировании скрипты используют настроенные `ANDROID_HOME`, `JAVA_HOME` и `PATH`; соседний файл окружения необязателен.
- Прокси-ядро — Tachyon. Пакетный мост HEV преобразует TUN в SOCKS; автоматической подмены ядра нет.
- Официальные нативные артефакты готовит `tooling/prepare_native.py` с проверкой SHA-256. Байты ядра сохраняются неизменными.
- Бинарники ядра, `.local`, APK, пользовательские профили и ключи подписи остаются вне Git.
- `tooling/Build-Android.ps1` по умолчанию собирает ARM64 APK для телефонов; `-Architecture x64` — для эмулятора, `-Architecture universal` — обе ABI. Не сохранять отладочные символы всех `.so`: побайтовое сохранение требуется только для Tachyon и HEV.
- После изменений выполняются `flutter analyze`, `flutter test` и затронутая Android-сборка.
- Пользовательские версии приложения — SemVer (`0.1.0`), задаются в `pubspec.yaml`. Передаваемые пользователю APK собираются через `tooling/Build-Android.ps1`: Android `versionCode` и номер `bN` возрастают независимо от даты. После перехода с версий по дате `versionCode` не уменьшается, чтобы сохранялась установка поверх старого APK. Версия стороннего Tachyon сохраняет имя автора.
- Проверка VPN требует реального запуска на Android и трафика. Сборка APK и тесты UI подтверждают только свои слои.
- Нативные тесты запускаются только через `tooling/Test-Native.ps1`: отдельный пакет `.checks`, проверка APK до запуска, обязательный `--no-uninstall`, затем удаление только `.checks`. Flutter может запомнить ID предыдущего APK для очистки; обычный пакет с профилями нельзя передавать раннеру на удаление.
- Нативные тесты выполняются на эмуляторе; на POCO устанавливается только проверенная release-сборка основного клиента.
